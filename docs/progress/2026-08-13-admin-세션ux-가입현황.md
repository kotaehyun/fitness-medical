## 결과

슈퍼계정 `admin01`이 **일반 회원 가입 현황 + 전문직 승인/해제**를 `/admin` 한 화면에서 봄. 로그아웃, 역할 홈, 401/403 구분, 회원/전문가 약관 분리.

상세 보고: [`../report/2026-08-13-admin-auth-session-가입현황.md`](../report/2026-08-13-admin-auth-session-가입현황.md).

## 작업한 파일

**백엔드**
- `AccountRole.ADMIN`, 공개 가입 불가, 시드 `admin01` / `password123`
- `AdminController` / `AdminService` / `AdminMemberResponse`
  - `GET /api/admin/members`
  - `GET /api/admin/professionals`
  - `POST .../verify`, `POST .../revoke`
- `SecurityConfig` — `/api/admin/**` `hasRole("ADMIN")` (**`/api/**` permitAll보다 앞**), 미인증 401 JSON / 권한없음 403 JSON
- `AuthController` `POST /logout` — SecurityContext + 세션 invalidate, 204
- ERD role에 ADMIN, README 데모 표

**프론트**
- `useAuthSession.js` — 데모 vs `/auth/me`, `homePath`, logout, `cacheAuthAccount`
- `AdminVerificationPage.jsx` — 요약 카드 + 회원 리스트 + 전문직 승인
- `PrivacyPage.jsx` — `/privacy/member`, `/privacy/professional`
- Landing `/` 로그인 시 역할 홈으로 `Navigate`
- 미인증 전문가: `useMembers({ enabled })`, 대기 StateView
- `PlaceholderPage`/`AppShell` `workspaceLabel?` (checkJs 필수 오류 수정)

## 설계 결정

- ADMIN은 회원 CRUD API를 안 씀. 승인·현황만. `assertCanAccessMember`에서 ADMIN → 403.
- 응답에 password·키·체중·면허번호 없음.
- 학원 “직접 칠” = Account 규칙·authz. 로그아웃/랜딩/약관/401 엔트리포인트는 글루.

## 진행 중 겪은 문제와 해결

1. **로그인해도 한 명만 되는 것처럼 보임 + 랜딩이 다시 로그인**  
   `/auth/me` 401이 React Query에 남아 ProtectedRoute가 `/login`으로 보냄. AppShell 이름이 `김순자` 하드코딩. 로그아웃 없음.  
   → 로그인 성공 시 `setQueryData`. 실 `displayName`. logout 버튼. 이미 로그인된 `/login`은 폼 대신 대시보드/로그아웃.

2. **로그인했는데 `/`가 회원 마케팅(김순자)처럼 보임**  
   랜딩이 세션을 안 봄.  
   → 로그인 상태면 `homePath(role)`로 `Navigate`. 로고도 역할 홈.

3. **콘솔 `GET /api/auth/me` 403**  
   Spring 기본: 미인증도 AccessDenied **403**. REST에선 미인증=401.  
   → `authenticationEntryPoint` 401 JSON `"로그인이 필요합니다."`  
   → 프론트 401/403이면 `getCurrentAccount()` `null`.  
   게스트 DevTools에 401이 한 번 찍히는 건 JSESSIONID 없는 `/me`라 **정상**. 완전히 숨기긴 어려움.

4. **콘솔 `/auth/me` 401 + `/api/members` 403 반복 (미인증 전문가)**  
   가입 직후 PROFESSIONAL이 대시보드에서 `useMembers()`를 무조건 호출. 서버는 verified 아니라 403.  
   → `canListMembers`일 때만 `useMembers({ enabled })`. 아니면 대기 안내.

5. **`Rendered more hooks than during the previous render`**  
   `useMembers` 안에서 `useAuthSession()`을 호출. enabled에 따라 훅 개수가 달라짐.  
   → 페이지에서 `useAuthSession` 후 `enabled`만 넘김. `useMembers`는 `useQuery`만.

6. **관리자 화면에 방금 가입한 전문가가 안 보임**  
   로컬 H2 `jdbc:h2:mem:...` + `ddl-auto: create-drop`. `admin01` 넣으려고 **서버 재시작**하면 공개 가입분 전부 삭제. 시드만 남음 (`member01`, `trainer01`, `doctor01`, `admin01`).  
   → 버그 아님. 재시작 없이 다시 가입하거나, 시드 전문가로 해제→승인 테스트.  
   증상: `GET /api/admin/professionals`에 trainer01/doctor01만.

7. **Vite `Failed to resolve import "../pages/admin/AdminVerificationPage"`**  
   파일은 있는데 HMR이 NFC/NFD 한글 경로(`개발`) 때문에 순간 miss.  
   → touch / 새로고침 후 정상. `npm run build` 성공.

8. **checkJs: `workspaceLabel` required (`router.jsx` PlaceholderPage)**  
   기본값 없는 인자 = 필수. 전문가 `PlaceholderPage`는 라벨을 안 넘김.  
   → JSDoc `workspaceLabel?` + `= undefined`. `npm run build` + lint OK.

9. **bootRun kill 시 `BUILD FAILED`**  
   재시작하려고 프로세스 죽인 로그. 앱 컴파일 실패 아님. 새 기동 `Started FitnessMedicalApplication`이면 OK.

10. **`/api/admin/**`를 `/api/**` permitAll 뒤에 두면 관리자 API가 열림**  
    matcher 순서.  
    → `hasRole("ADMIN")`를 permitAll **앞**에 둠.

## 테스트 흐름

1. 전문가 가입 → 로그인 → “인증 대기” (회원 목록 API 안 나감)
2. `admin01` / `password123` → `/admin`에서 승인
3. 전문가 재로그인 → 회원 목록 OK
4. 관리자 해제 → 다시 대기
5. `/admin` 상단에서 MEMBER 가입 현황 (`member01` + 공개 가입 회원)

시드 면허와 겹치면 409. 예시 면허 `987654`, 자격 `SP22005678`.
