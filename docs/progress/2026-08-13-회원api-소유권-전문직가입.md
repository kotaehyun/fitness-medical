## 결과

`/api/members/**`는 **로그인 필수**. MEMBER는 본인 `memberId`만, PROFESSIONAL은 **`professionalVerified=true`일 때만** 전체 회원. 피드백 `author`/`role`은 세션 Account에서 채움(클라이언트가 위조 못 함).

공개 가입 전문가는 면허/자격 **형식만** 검사하고 항상 `verified=false`. 기존 `memberId` 연결 금지. 면허 UNIQUE + 레이스 **409**.

Codex가 `d897ae2`를 두 번 리뷰해서 P0/P1을 지적 → 코드 수정은 `a90684c`에 반영. 리뷰만 하고 고치지 않은 상태가 아님.

## 작업한 파일

- `SecurityConfig` — `/api/members/**` authenticated, 피드백 POST PROFESSIONAL
- `MemberAuthorizationService` — `assertCanAccessMember`, `requireProfessional` + `assertProfessionalVerified`
- `AccountService` — PHYSICIAN 면허 필수(숫자 5~10), TRAINER 자격 우대(선택, `SPxxxxxxxx` 형식), 공개 가입 verified=false, memberId 거부, ADMIN 공개 가입 거부(이후)
- `Account` — `uk_accounts_license_number`
- `GlobalExceptionHandler` — `DataIntegrityViolationException` → 409
- 테스트: `AccountServiceTest`, `MemberAuthorizationServiceTest`, `AuthControllerTest`

## 설계 결정

- 형식 OK ≠ 전문가 API. 관리자 승인 전 403 `"전문직 인증이 완료되지 않았습니다."`
- 공개 가입에 memberId를 받으면 다른 회원 계정을 훔칠 수 있음 → **무조건 400**.
- 트레이너 자격은 우대(없어도 가입). 전문의 면허는 필수.
- `[하드코딩]` / `[핵심로직]` region: 학원에서 “직접 친 규칙”을 IDE에서 접을 수 있게.

## 진행 중 겪은 문제와 해결

1. **Codex P0: 공개 가입 PROFESSIONAL이 형식만 맞으면 verified=true**  
   누구나 전문가 API.  
   → 공개 가입은 항상 `verified=false`. 시드 `trainer01`/`doctor01`만 true.

2. **Codex P0: 미인증 PROFESSIONAL이 전체 회원 조회**  
   `hasRole`만 보면 역할만 PROFESSIONAL이면 통과.  
   → `MemberAuthorizationService`에서 verified 검사.

3. **Codex P1: 공개 가입 memberId로 기존 회원 가로채기**  
   → `resolveMember()`에서 memberId 있으면 `InvalidRequestException` 400.

4. **Codex P1: 면허 중복 가입**  
   → UNIQUE + exists 검사. 레이스는 `DataIntegrityViolationException` → 409 (`dd2ca5f`).

5. **H2 UNIQUE + 여러 NULL license**  
   트레이너 자격 없이 여러 명 가입. SQL 표준은 UNIQUE에서 NULL 여러 행 허용. Boot 3.5 H2에서 OK.

6. **`git pull origin dev` dirty tree 실패**  
   로컬 수정 + 원격 UNIQUE 409·주석 커밋.  
   → stash → fast-forward `d897ae2..72720fc` → stash pop.  
   충돌: `AccountService.java`, `AuthControllerTest.java`.  
   → 로컬 미인증+memberId 거절 유지 + 원격 409 테스트/`[하드코딩]` 유지. 커밋 `a90684c`.

7. **가입 시 시드 면허 409**  
   UI에 `SP21001234` / `123456` 쓰면 시드와 충돌.  
   → 예시 `SP22005678` / `987654`.

8. **checkJs `'requestError' is of type 'unknown'`**  
   → `instanceof Error` 후에 `.message`.

9. **리뷰만 보고 “dev에 안 들어갔다”고 착각**  
   push는 됐지만 P0/P1 **코드 수정은 안 한 상태**였음. 두 번째 동일 리뷰 = 아직 안 고침.  
   → `a90684c`로 고치고 push.
