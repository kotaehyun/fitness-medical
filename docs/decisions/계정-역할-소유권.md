# 결정: 계정·역할·소유권

1단계 [`member-create-request-필드-설계.md`](./member-create-request-필드-설계.md) 이후, 로그인·공개 가입·관리자 승인이 붙으면서 확정한 내용이다. 구현 전 리뷰는 [`../study/codeReview/step4-session-auth-review.md`](../study/codeReview/step4-session-auth-review.md)에 남기고 덮어쓰지 않는다.

## 배경

`Member`는 건강 기록 대상이고 `Account`는 로그인 주체다. 공개 API로 기존 회원을 가로채면 안 되고, 전문직은 회원 전체에 접근하므로 가입만으로 권한을 주면 안 된다.

## 결정

| 주제 | 결정 | 이유 |
|------|------|------|
| Account–Member | MEMBER만 `@OneToOne`. PROFESSIONAL·ADMIN은 `member == null` | 건강 데이터와 인증을 분리한다 |
| 공개 가입 `memberId` | 오면 400. MEMBER는 프로필로 **새** Member를 만든다 | 기존 회원 연결은 공개 API에서 금지 |
| 일반 회원 승인 | **하지 않는다.** 가입 즉시 본인 데이터만 사용 | MEMBER는 타인 기록에 접근하지 않음 |
| 회원 상태 「확인 필요」 | `MemberStatus.CHECK_REQUIRED` 기본값 | 건강 흐름 라벨이다. 관리자 승인 대기가 아님 |
| 전문직 공개 가입 | 항상 `professionalVerified=false` | 형식만 맞는 자격으로 전체 회원 API를 열지 않음 |
| 전문직 승인 | ADMIN이 `accounts.professional_verified`만 UPDATE | 학습용 수동 토글. 면허 조회·승인 로그 테이블 없음 |
| 세션 | HTTP Session + 쿠키. JWT 아님 | STUDY_TASKS 4단계. 프론트는 `credentials: 'include'` |
| `/api/ai/**` | Spring에서 `authenticated()`. FastAPI `:8000`은 로컬 전용 | 생활 안내 RAG. 진단·처방 API가 아님 |
| local DB | 파일 H2 + `ddl-auto: update` | 재시작 후에도 공개 가입 유지. 시드 계정이 하나라도 있으면 DemoData 생략 |
| CSRF·Flyway | 로컬 시연에서는 미적용 | 운영 배포 전에 분리 |

## 권한 한 줄

- MEMBER → 연결된 `memberId`만 (`MemberAuthorizationService.assertCanAccessMember`)
- PROFESSIONAL + verified → 회원 목록·기록·피드백
- PROFESSIONAL + 미인증 → 403
- ADMIN → `/api/admin/**`만 승인/현황. 회원 건강 API는 이 역할로 열지 않음

## 하지 않는 주장

실제 면허 시스템 연동, 임상 검증, 의사 대체, 상용 의료 보안 완성이 아니다.

## 재검토 시점

담당 환자만 보기, 공유 동의, 감사 로그, CSRF, Flyway는 v1.0 이후다.
